# API routes

Every Next.js route handler under `app/` (`route.ts` files), with its HTTP methods and the authentication mechanism detected in the handler.

Generated by `scripts/gen/api-routes.ts` (`bun run gen` in `docs-site/`). The summary is the leading comment of the route file, when there is one. Auth is detected from the helper each handler calls:

| Mechanism | Meaning |
|---|---|
| `user-session` | `getCurrentUserId()` / `getCurrentUser()` — Supabase session, or the shared `ANONYMOUS_USER_ID` when `ENABLE_AUTH=false` (lab). "via helper" means the check lives in a server action the route calls. |
| `ingest-token` | `checkIngestAuth()` — bearer `INGEST_API_TOKEN`, service-to-service (search tool → advanced search, ingestor worker). |
| `cron-secret` | `requireCronSecret()` — bearer `MEMORY_CRON_SECRET`, scheduled maintenance jobs. |
| `signed-url` | HMAC-signed capability URL for uploaded files (`UPLOADS_URL_SECRET`). |
| `supabase-otp` | Supabase auth callbacks. |
| `public` | No auth call detected in the file. Check the handler before assuming it is safe to expose. |
